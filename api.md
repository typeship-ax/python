# typeship — API reference

Version 0.4.0. Generated by typeship; regenerate rather than editing.

Methods return the payload directly and raise on failure: a documented error response raises its typed exception, and a network failure raises `TransportError`.

## generate

### `client.generate.run(*, spec, outputs, package_name=None, config=None)`

Generate a package from a spec

`POST /generate`

Stateless generation: nothing is stored. Returns the full generated
package as files. Works without an API key: anonymous calls generate
the first 25 operations, rate limited per IP address, and the
response's `limits` object says what was held back and where to lift
it; anonymous calls from a spec URL also carry `claim.url`, a link
that turns the run into a project once a person signs in. With a key, the free plan generates the first 25 operations and
paid plans generate the whole spec. A present but invalid key is a
401, not a downgrade to anonymous.

Body (required):

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `spec` | `SpecInput` | yes |  |
| `outputs` | `List[OutputId]` | yes | Outputs for one delivery package. Choose one SDK output, or TypeScript SDK, CLI, and MCP in any combination. Linked projects can generate outputs in all ecosystems. |
| `package_name` | `str` | no | npm name override for the generated package. |
| `config` | `Config` | no |  |

Returns: `GenerationResult`
Errors: `UnauthorizedError` (401), `ForbiddenError` (403), `PayloadTooLargeError` (413), `UnprocessableEntityError` (422), `RateLimitedError` (429), `ApiResponseError` (default)

### `client.projects.create(*, name, outputs, spec_url=None, source=None, packages=None, auto_regen=None, spec_patches=None, mcp_enabled=None, relay_enabled=None, config=None)`

Create a project

`POST /projects`

Stores a URL- or repository-sourced project. Free includes one stored project, every selected output, and the first 25 operations, while keeping manual and automatic regeneration, history, destination pull requests, and preview checks. Stateless POST /generate does not consume this slot. Pro adds projects and the whole spec.

Body (required):

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | `str` | yes |  |
| `spec_url` | `str` | no | Spec location for a URL-sourced project. Provide this or source; a project with neither has nothing to generate. |
| `source` | `Source` | no |  |
| `outputs` | `List[OutputId]` | yes | First-class outputs to keep current. Any non-empty combination is valid. |
| `packages` | `Packages` | no |  |
| `auto_regen` | `bool` | no |  |
| `spec_patches` | `List[SpecPatch]` | no |  |
| `mcp_enabled` | `bool` | no | Requires the MCP output and Enterprise. |
| `relay_enabled` | `bool` | no | Requires the CLI output and Pro. |
| `config` | `Optional[Config]` | no |  |

Returns: `Project`
Errors: `BadRequestError` (400), `UnauthorizedError` (401), `PaymentRequiredError` (402), `ForbiddenError` (403), `RateLimitedError` (429)

### `client.projects.generate(project_id)`

Generate outputs and open pull requests

`POST /projects/{project_id}/generations`

Resolves the project's URL or repository source, generates every
configured delivery package, stores each result in the project's history,
and attempts to open a pull request in every configured destination.
When the complete generated tree already matches a destination, no
commit, branch, or pull request is created and that generation reports
`pr_status: no_changes`. This is the same pipeline automatic
regeneration runs after a source change.

| Parameter | In | Type | Required | Description |
| --- | --- | --- | --- | --- |
| `project_id` | path | `ProjectId` | yes |  |

Returns: `ProjectsGenerateResponse`
Errors: `UnauthorizedError` (401), `PaymentRequiredError` (402), `ForbiddenError` (403), `NotFoundError` (404), `UnprocessableEntityError` (422), `RateLimitedError` (429), `InternalServerError` (500)
